# Skill4 × 搭子双向同步设计

## 目标

保留现有 Skill4 网页作为学习计划和日报入口，并让 Android 搭子在不依赖电脑常开的情况下，读取同一份学习状态、根据它主动联系用户，并把聊天中确认的学习进度写回 Skill4。

## 不做什么

- 不把完整聊天记录上传到 GitHub 或网页。
- 不让模型直接改写计划文本、删除日报或自动完成含义不明确的任务。
- 不要求用户另购云服务器。

## 共享内容

| 内容 | 来源 | 两端行为 |
| --- | --- | --- |
| 每日计划 | Skill4 的周任务模板 | 网页和 App 使用同一份带稳定 ID 的计划导出 |
| 完成状态 | 网页勾选或聊天确认 | 立即本地生效，联网后双向同步 |
| 学习时长与晚报 | Skill4 表单或搭子对话 | 按日期同步；对话更新先生成明确记录 |
| 待补任务 | 由未完成计划推导 | 两端都可展示，不能被模型直接删除 |
| 搭子提示上下文 | 共享学习状态 + 手机本地聊天 | 只把最近学习状态供模型参考；聊天原文仍留手机 |

## 同步架构

```text
Skill4 网页 ─┐
             ├─ GitHub 仓库中的加密同步文件 ─ Android 搭子
搭子 App ────┘
```

GitHub 已是 Skill4 的发布和日报同步位置，因此第一版不增加付费服务。静态计划继续公开读取；会暴露学习内容的完成状态、时长和日报改为一个加密数据文件。网页和 App 都先写自己的离线缓存，再在可联网时上传或拉取合并。

## 安全与隐私

1. 新的同步状态使用 AES-GCM 加密；GitHub 中只保存密文、格式版本和非敏感修订号。
2. GitHub 写入令牌与同步密钥永不写入源码、提交记录、日志或 DeepSeek 请求。
3. Android 侧使用现有 Android Keystore 加密保存令牌和同步密钥；网页侧仅保存在当前浏览器。
4. 当前仓库的历史 `data/*.json` 已含明文晚报。新功能不再新增明文日报；旧历史的清理必须由用户单独确认，因为删除或改写 Git 历史是不可逆操作。
5. DeepSeek 只收到生成回复或主动提醒所必需的“今日计划、已完成项、待补项、近期日报摘要”，不收到 GitHub 令牌或同步密钥。

## 数据模型

计划项从“任务文字”升级为稳定 ID，例如 `2026-08-18/w3/mon/psychology-ch9`。显示文字仍由 Skill4 管理，ID 只用于同步与冲突处理。

共享状态的逻辑模型如下：

```json
{
  "schemaVersion": 1,
  "revision": 17,
  "tasks": {
    "2026-08-18/w3/mon/psychology-ch9": {
      "done": true,
      "updatedAt": "2026-08-18T13:20:00Z",
      "source": "companion"
    }
  },
  "dailyReports": {
    "2026-08-18": {
      "hours": "3.5",
      "summary": "…",
      "problem": "…",
      "tomorrow": "…",
      "updatedAt": "2026-08-18T14:30:00Z"
    }
  }
}
```

任务状态按单项的最后更新时间合并；晚报按日期记录的最后更新时间合并。上传遇到 GitHub 文件版本冲突时，客户端重新拉取、合并、重试一次；仍失败则保留本地待同步队列并提示用户，不丢数据。

## 交互约定

- App 打开、生成主动消息前、发送聊天后会尝试刷新同步状态；无网时使用最后成功同步的缓存。
- 网页打开时拉取一次；勾选任务、保存晚报时立即写本地并后台同步。
- 用户在聊天中清楚表达“普心第 9 章学完了”时，搭子记录为已完成，并说“记上了：普心第9章完成，不对就说撤回”。
- 用户表达不清楚时，搭子先问一句，例如“是把今天的统计第5章也标为完成，还是只看了一部分？”
- 撤回、取消完成、修改晚报均作为正常同步操作。
- 搭子提示会针对真实状态：早上问计划、下午询问具体未完成项、晚上根据实际完成情况写收工/晚报；不因一次未回复就指责用户，也不产生暧昧表达。

## 设置与首次连接

Skill4 新增“搭子同步”设置，App 新增“连接 Skill4”设置。首次连接时：

1. 在网页生成一次同步密钥并显示连接二维码/连接码。
2. App 扫描或粘贴连接码，并在本机安全保存密钥。
3. 用户创建一个仅能访问 `00m-k/skill4` 内容读写权限的 GitHub fine-grained token，分别在网页和 App 输入一次。令牌用于写加密状态，不能访问 DeepSeek Key。
4. App 与网页各做一次导入：现有浏览器 localStorage 迁入共享状态，重复项按时间合并；成功后显示“已同步”。

后续不需要电脑开机。GitHub 不可访问时仍能分别使用，网络恢复后同步。

## 长期记忆边界

本次绑定让搭子拥有可靠的“学习记忆”：计划、连续性、拖延点、完成率、近日报告。它不等同于保存所有聊天内容。聊天偏好和生活信息的可管理长期记忆将作为后续独立功能，必须可查看、编辑、删除和一键清空。

## 验收

1. 网页勾选一项后，App 刷新能看到同一项完成；反向同样成立。
2. 任一端保存晚报后，另一端显示相同内容。
3. 无网更新不丢失，恢复网络后能合并同步。
4. 两端同时改不同任务时都保留；同一任务以最后一次明确操作为准。
5. App 的主动提示和正常聊天都能读取同步状态；不上传完整聊天。
6. GitHub 仓库中不出现 DeepSeek Key、GitHub token、同步密钥或明文新日报。
